# Generate and Upload Stake Math

This guide applies to any game under `games/<game_id>/`. Game-specific scripts and tuning values remain authoritative when they differ from the examples below.

## 1. Prerequisites

- Python 3.12+
- `pip`
- `make` (recommended)
- Rust/Cargo when the game uses the optimizer
- `zstd` for compressed-book integrity checks
- Access to the Stake Engine Admin Control Panel (ACP)

From the repository root:

```bash
make setup
source env/bin/activate
```

Do not commit credentials, local `.env` files, generated test output, or production secrets.

## 2. Check the game configuration

Before generating, inspect:

```text
games/<game_id>/game_config.py
games/<game_id>/gamestate.py
games/<game_id>/run.py
```

Confirm:

- `game_id` is the Stake game ID.
- Every bet mode has the correct name, cost, RTP, and max win.
- Simulation counts and thread counts are appropriate.
- Production output uses zStandard compression (`compression = True`).
- Optimization/weighting is enabled when the game requires it.
- Event names and payloads match the frontend playback contract.

Book values use a scale of `100`: `1150` means `11.50x`. Do not use the wallet/API scale (`1,000,000`) in books or lookup tables.

## 3. Run a small development batch first

Use a small simulation count and uncompressed output to inspect events quickly. Exact controls differ by game; they are normally in `run.py` or game-specific environment variables.

Typical development settings:

```python
num_threads = 1
compression = False
num_sim_args = {
    "BASE": 100,
    "BONUS": 100,
}
```

Run from the repository root:

```bash
GAME_ID=0_0_your_game
python3 "games/$GAME_ID/run.py"
```

Equivalent Make command:

```bash
GAME_ID=0_0_your_game
make run GAME="$GAME_ID"
```

Inspect `games/<game_id>/library/books/`. Verify board states, event order, final wins, feature entry/exit, and replay determinism before starting a production run.

## 4. Run production generation

Set the game's production simulation counts, compression, threading, optimization, and analysis options. Then run:

```bash
GAME_ID=0_0_your_game
python3 "games/$GAME_ID/run.py"
```

Some games expose environment variables for simulation and thread counts. Use only the variable names documented by that game's `run.py`.

Production runs may need substantial time, RAM, and disk. Check free disk space first:

```bash
df -h .
```

Do not run two generators against the same `games/<game_id>/library/` directory. Do not interrupt while chunks are being combined, lookup tables are being weighted, or configs are being written.

If simulation completed but weighting stopped, use the game's `reweight_only.py` when present:

```bash
python3 "games/$GAME_ID/reweight_only.py"
```

Reweighting is safe only when the existing books were generated by the current math code. Any payout, board, RNG, event, or mechanic change requires new books first.

## 5. Required upload package

The upload directory is:

```text
games/<game_id>/library/publish_files/
```

It must contain `index.json` at its root. Each mode referenced by the index needs:

```text
index.json
books_<MODE>.jsonl.zst
lookUpTable_<MODE>_0.csv
```

Minimum `index.json` shape:

```json
{
  "modes": [
    {
      "name": "BASE",
      "cost": 1.0,
      "events": "books_BASE.jsonl.zst",
      "weights": "lookUpTable_BASE_0.csv"
    }
  ]
}
```

Every compressed JSONL record must contain:

```json
{
  "id": 1,
  "events": [],
  "payoutMultiplier": 0
}
```

Every lookup row must be unsigned integers in this order:

```csv
simulation_id,weight,payout_multiplier
```

Requirements:

- Book IDs are unique.
- Every lookup ID exists in its mode's book.
- Every reachable book has a positive weight.
- Lookup payout exactly equals the book's `payoutMultiplier`.
- Mode names and filename case exactly match `index.json`.
- `index.json` uses relative filenames, not local absolute paths.

Uncompressed books, temporary chunks, reports, source files, and force files are not part of the minimum ACP math package unless Stake specifically requests them.

## 6. Validate before upload

Run repository tests:

```bash
python3 -m pytest
```

Run game-specific validators when available:

```bash
find "games/$GAME_ID" -maxdepth 1 -name 'validate_*.py' -print
# Run each validator listed above, for example:
python3 "games/$GAME_ID/validate_your_game_contract.py"
python3 "games/$GAME_ID/validate_your_game_artifacts.py"
```

Check all compressed books:

```bash
zstd -t "games/$GAME_ID"/library/publish_files/books_*.jsonl.zst
```

Check that every file referenced by `index.json` exists:

```bash
python3 - "games/$GAME_ID/library/publish_files" <<'PY'
import json
import sys
from pathlib import Path

root = Path(sys.argv[1])
index = json.loads((root / "index.json").read_text())
assert index.get("modes"), "index.json has no modes"
for mode in index["modes"]:
    for key in ("events", "weights"):
        path = root / mode[key]
        assert path.is_file(), f"missing {mode['name']} {key}: {path}"
print(f"PASS: {len(index['modes'])} modes; all referenced files exist")
PY
```

Also verify the generated RTP, hit rate, max-win reachability, feature frequencies, zero-win share, and mode costs against the approved math specification. A successful generator exit alone is not release approval.

## 7. Upload through Stake Engine ACP

1. Sign in to Stake Engine and open the correct game/project.
2. Create or select the intended game version/environment.
3. Open its math/RGS upload area. ACP labels may change, but the selected upload root must be `library/publish_files/`.
4. Upload `index.json` plus every book and lookup file referenced by it. Preserve filenames exactly.
5. Wait for Stake's format, hash, ID, payout, and RTP checks to finish.
6. Confirm the ACP mode list, costs, RTP values, round counts, and max win match the approved specification.
7. Test `/play` for every mode and replay representative rounds in the matching frontend build.
8. Publish/activate the version only after math, frontend playback, replay, and compliance checks pass.

Never override a failed RTP, hash, payout, or book-length check without explicit math and release approval. Upload to a test/staging environment before production.

## 8. Legacy S3 uploader

`uploads/aws_upload.py` is a legacy/alternate internal S3 path, not the default ACP workflow. Use it only when your Stake Engine contact explicitly requires it and supplies the bucket and credentials. Never commit `uploads/.env`.

## Release checklist

- [ ] Current branch/commit recorded
- [ ] Approved math parameters used
- [ ] Production books regenerated after the last math change
- [ ] Lookup tables generated from those exact books
- [ ] `index.json` references all and only intended modes
- [ ] Contract tests pass
- [ ] Artifact tests pass
- [ ] All `.zst` files pass integrity checks
- [ ] RTP, hit rate, max win, and feature frequencies approved
- [ ] Frontend handles every emitted event
- [ ] Replay tested
- [ ] ACP validation passes
- [ ] Staging smoke test passes before production activation
